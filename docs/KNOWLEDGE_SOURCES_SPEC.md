# Lumina Edit Pro 知识来源功能技术方案规范 (Knowledge Sources & Web Clipper Specification)

> **定位**：将任意外部高价值网页、微信公众号图文、小红书笔记（含贴图）、飞书云文档等内容，以**像素级排版保真 + 资源 100% 离线本地化 + 结构化元数据 (Frontmatter)** 的形态，完整沉淀为 Lumina Edit Pro 的 Markdown 知识资产，并作为后续 AI 创作的知识上下文池。

---

## 1. 核心架构与设计原则

### 1.1 核心三大原则
1. **排版与语义高保真**：保留原文章标题、作者、发布日期、多级标题、表格、代码高亮语言、公式（LaTeX）、引用块，自动生成标准 YAML Frontmatter。
2. **彻底资产本地化（无本地化，不剪藏）**：所有图片、SVG、贴图、音视频等外部静态资源全部并发下载并存储到当前文档关联的工作区 `.assets` 目录，彻底杜绝微信 `qpic` 403 防盗链、飞书临时鉴权 CDN 过期、小红书图片失效等问题，实现 100% 离线可用。
3. **双引擎自适应采集**：
   - **快速静态通道 (Fast Crawler Engine)**：针对 SSR 渲染、无复杂反爬的公开链接（微信公众号、知乎专栏、技术博客），通过 Rust/Node 带有浏览器真实请求头的网络客户端，毫秒级抓取。
   - **动态仿真渲染通道 (WebView Engine)**：利用 Tauri 的 WebView 能力，针对重度 SPA、动态 DOM 渲染或需要登录态的页面（小红书、飞书公开/私有文档），在隔离环境中完整渲染并提取 Block AST。

## 3. 平台适配专项规范

### 3.1 微信公众号图文 (`mp.weixin.qq.com`)
- **数据源提取**：
  - 核心容器锁定在 `#js_content`；
  - 标题提取自 `#activity-name` 或 `meta[property="og:title"]`；
  - 公众号作者提取自 `#js_name`，发布日期提取自 `script` 变量或 DOM 时间戳。
- **图片与懒加载处理**：
  - 识别微信专有的 `data-src` 属性，提权替换标准的 `src`；
  - 检查 `data-type="png/jpeg/webp"`，确保重写后的本地图片拥有正确的文件扩展名；
  - 下载图片时必须附加 `Referer: https://mp.weixin.qq.com/` 请求头或无 referer 请求，规避微信 CDN 403 防盗链。
- **特殊排版转义**：
  - 过滤关注引导、点赞在看、底部小程序卡片与二维码广告；
  - 提取微信代码块中的原始换行与缩进，生成标准 Markdown ` ``` ` 代码块；
  - 将微信公式 SVG/图片转化为标准的内联或块级 LaTeX 语法。

### 3.2 小红书图文/贴图笔记 (`xiaohongshu.com` / `xhslink.com`)
- **短链还原**：针对移动端复制的 `xhslink.com` 短链接，通过 HTTP HEAD/GET 跟踪 302 自动重定向为标准的 `xiaohongshu.com/explore/...` 链接。
- **数据抓取通道**：
  - **Level 1 (极速状态提取)**：解析页面内嵌的 `window.__INITIAL_STATE__`。
    - 从 `noteView.note` 提取：`title`（标题）、`desc`（正文与 `#话题`）、`imageList`（高清无水印图片原图 CDN 数组）、`user.nickname`（作者）、`interactInfo`（点赞收藏数据）。
  - **Level 2 (Tauri WebView 仿真降级)**：若触发反爬验证码（如滑动验证），唤起轻量内置 WebView 窗口，待用户完成验证后自动提取完整的 Notes 状态对象，并存储凭证。
- **排版呈现**：
  - 笔记正文转换为规范 Markdown；
  - 多图贴图生成高保真图集流（支持双列/多列网格排版或有序贴图列表）；
  - 话题标签转为 YAML Frontmatter 中的 `tags` 数组。

### 3.3 飞书云文档 (`feishu.cn` / `larksuite.com`)
- **双模解析体系**：
  - **公开分享链接**：通过 Tauri 后台 WebView 载入，等待客户端 Block 树渲染完毕，注入 Block AST 提取脚本，深度遍历飞书的节点树。
  - **私有企业文档（OpenAPI 模式）**：支持用户在设置中填入自建应用凭据，调用飞书开放平台官方接口 `GET /open-apis/docx/v1/documents/:doc_id/blocks`，直接获取官方结构化 JSON 树。
- **飞书专属富文本映射表**：
  | 飞书组件 | Markdown 目标格式 |
  | :--- | :--- |
  | 高亮块 (Callout) | GitHub Alert 语法 (`> [!NOTE]` / `> [!TIP]`) |
  | 任务清单 (Todo) | GFM TaskList (`- [ ]` / `- [x]`) |
  | 复杂表格 (Table) | 遵循 Lumina 排版规范的 GFM 表格 (`\| --- \| --- \|`) |
  | 行内/独立公式 | LaTeX 语法 (`$...$` 与 `$$...$$`) |
  | 代码块 (Code Block) | 带语言标记的代码围栏 (````lang ... ````) |
  | 分栏布局 (Columns) | 转换为标准段落与分割线，避免丢失内容 |

### 3.4 贴图与多媒体资源本地化引擎 (Asset Localizer)
- **下载与哈希去重**：
  - 并发度限制为 3~5 个任务，避免触发目标站点的防刷限流；
  - 对下载到的二进制 Buffer 进行 SHA-256 计算，截取前 12 位生成唯一文件指纹（如 `img-a8f3b20c1d.png`）；
  - 自动通过 Content-Type 及二进制头部 Magic Bytes 检测文件真实格式（`.png`, `.jpg`, `.webp`, `.svg`, `.gif`）。
- **存储与相对路径转换**：
  - 统一保存至当前工作区或单文件的 `.assets` 目录；
  - 自动将 Markdown 中的远程链接重写为本地相对路径：`![](./.assets/img-a8f3b20c1d.png)`；
  - 若部分图片网络错误下载失败，保留原始 URL 并在末尾注释告警，绝不中断文档保存流程。

## 4. UI/UX 交互规范

1. **入口配置**：
   - 顶部导航栏专属图标 `知识来源 (Knowledge Source)`；
   - 全局快捷键：`Ctrl + Shift + I` (Windows/Linux) / `Cmd + Shift + I` (macOS)；
   - 监听剪贴板：切回应用时识别到符合规则的 URL，弹出轻量询问提示。
2. **导入对话框 (`KnowledgeSourceModal`)**：
   - **智能识别输入**：输入 URL 后自动识别平台（微信公众号、小红书、飞书、通用网页）；
   - **抓取预览**：展示提取出的文章标题、作者、发布日期、封面、字数及图片数量；
   - **目标模式**：
     - `创建为工作区新文档`：自动生成规范文件名（如 `[公众号] xxx.md`）；
     - `插入到当前光标处`：仅插入处理后的 Markdown 正文及图片。
   - **本地化选项**：默认勾选 `[√] 离线保存图片至 .assets 目录`；
   - **导入执行动效**：分步进度条展示 `正在解析网页 -> 正在提取图文 -> 正在本地化图片 (3/8) -> 保存完成`。
3. **知识库集成**：
   - 剪藏入库的文档自动记录元数据，后续可直接挂载到右侧 AI 面板进行 RAG 知识检索与智能写作。
